# TASK T1.3 — Database for admin-managed configuration (TASKS.md row 1.3). PHP lane.

Goal: durable, versioned storage for config documents (the wizard first; planner params, catalog, texts... later) following convention §7.2:
`draft -> published`, every publish creates a new immutable version, rollback is possible, everything is audited. This task is ONLY schema + models + enums +
factories + DB-level invariants + tests. Business logic (create draft, validate against the config schema, publish, rollback, HTTP endpoints) is task T1.4: do NOT implement it.

## Tables (migrations with working `down()`, timestamps in UTC, utf8mb4, MySQL 8.4 AND SQLite compatible — tests run on sqlite, dev/prod on MySQL)
1. `config_documents`: `id`, `key` (string 64, e.g. `wizard`), `scope` (string 64, default `global`; reserved for per-tenant/per-site configs later), `current_version_id`
   (nullable, the PUBLISHED version in use), `timestamps`. UNIQUE (`key`,`scope`).
2. `config_versions`: `id`, `config_document_id` (FK -> config_documents, ON DELETE CASCADE), `version` (unsigned int, 1-based, increasing per document),
   `status` (`draft` | `published` | `archived`, string column, not a DB enum), `is_draft` (nullable boolean: `1` for a draft, NULL otherwise — see invariant), `schema_version` (unsigned small int),
   `payload` (JSON, NOT NULL), `payload_hash` (char 64, sha256 of the canonical payload), `label` (nullable string 120), `created_by` / `published_by` (nullable FK -> users, ON DELETE SET NULL),
   `based_on_version_id` (nullable self FK, ON DELETE SET NULL), `published_at` (nullable timestamp), `timestamps`.
   Invariants enforced BY THE DATABASE: UNIQUE (`config_document_id`,`version`); **at most one draft per document** via UNIQUE (`config_document_id`,`is_draft`) (multiple NULLs are allowed in both
   MySQL and SQLite, so only one row with `is_draft = 1` can exist); index on (`config_document_id`,`status`). Then add the FK `config_documents.current_version_id -> config_versions.id` (ON DELETE SET NULL)
   in a separate migration/step so creation order works on both engines.
3. `config_audit_logs`: `id`, `config_document_id` (FK cascade), `config_version_id` (nullable FK, SET NULL), `user_id` (nullable FK users, SET NULL), `action` (string 32), `summary` (nullable JSON),
   `request_id` (nullable string 64 — the X-Request-Id of the HTTP request), `created_at` (no updated_at: audit rows are append-only). Index (`config_document_id`,`created_at`).
Never store IP addresses or user agents (privacy).

## Code
- Enums (`app/Enums/`): `ConfigVersionStatus` (Draft, Published, Archived) and `ConfigAuditAction` (CreateDraft, UpdateDraft, DiscardDraft, Publish, Rollback) — string-backed.
- Models (`app/Models/`): `ConfigDocument`, `ConfigVersion`, `ConfigAuditLog` with typed relations, `$fillable` that does NOT include `status`, `is_draft`, `payload_hash`, `published_at`, `current_version_id`
  (those are set only by code paths added in T1.4 using `forceFill`), casts (`payload` -> array, enums, datetimes), `@property` docblocks (Larastan level 6), `ConfigAuditLog` is read-only after creation
  (`UPDATED_AT = null`; updating or deleting a log row through Eloquent throws a LogicException — add a tiny model event guard).
  Helper `ConfigVersion::computePayloadHash(array $payload): string` = sha256 of the payload encoded with sorted keys at every level, `JSON_UNESCAPED_UNICODE|JSON_UNESCAPED_SLASHES` — deterministic regardless of key order;
  document that numbers/strings keep their type. Query scopes `drafts()`, `published()`.
- Factories (`database/factories/`) for the three models (sensible defaults, states `draft()`, `published()`, `archived()`).
- Everything follows the enforced conventions: `declare(strict_types=1)`, Larastan level 6, Pint, PHP 8.2, arch tests keep passing (add expectations for the new enums/models in `tests/Arch/ConventionTest.php` only if they are
  naturally covered; do not weaken existing ones). Use exact versions if you add any package (you should not need one).

## Tests (Pest, sqlite in memory via the existing guarded TestCase; do NOT touch the developer MySQL data)
- migrate up/down/up works (`Artisan::call('migrate:rollback')` then migrate) and leaves no tables behind on rollback.
- unique (`key`,`scope`); same key with another scope allowed; (`document`,`version`) unique; a second draft for the same document is rejected by the DB (QueryException) while any number of published/archived
  rows with `is_draft = NULL` are allowed; two documents may each have one draft.
- cascade: deleting a document deletes its versions and audit logs; deleting a user keeps versions/logs with NULL user; deleting the version referenced by `current_version_id` sets it to NULL.
- JSON: Japanese/Vietnamese/emoji payload round-trips byte-exact; nested arrays and numbers keep types (1 vs 1.5 vs "1" vs true vs null); a 1 MB payload round-trips; invalid payload (resource, NAN) is rejected before hitting the DB.
- `computePayloadHash`: key order independent (nested too), value sensitive (`1` vs `"1"`), stable known vector (hard-code the expected sha256 for a small payload), different for unicode normalisation differences (NFC vs NFD are different bytes -> different hash; document it).
- mass assignment: `ConfigVersion::create(['status' => 'published', 'is_draft' => null, 'payload_hash' => 'x', ...])` does NOT set those guarded columns.
- audit log immutability: update and delete through Eloquent throw; `created_at` set, no `updated_at`.
- factories produce valid rows; `drafts()`/`published()` scopes return the right rows.
- `php artisan migrate --pretend` for the MySQL connection prints SQL without errors (run it manually and paste the table DDL lines into the report; the reviewer verifies real MySQL behaviour).

## Acceptance
`make check-php` exits 0 twice, then ONE final full `make check` (see BRIEF section 3a for the shared-checkout rules). Sabotage (show failing output, restore): (1) remove the unique (`config_document_id`,`is_draft`) -> draft-uniqueness test fails;
(2) make the hash depend on key order (drop the recursive sort) -> hash test fails; (3) add `status` to `$fillable` -> mass-assignment test fails; (4) allow updating audit logs -> immutability test fails.
Run `php artisan migrate` (NOT `migrate:fresh`, never wipe) on the dev database at the end and report `php artisan migrate:status` output.

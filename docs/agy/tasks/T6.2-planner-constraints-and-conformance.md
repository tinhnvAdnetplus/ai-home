## A. DesignConstraints input (produced by backend AI, see docs/agy/tasks/T6.1-ai-backend.md for the JSON shape; implement the Zod schema `DesignConstraintsSchema` in `packages/planner/src/constraints.ts` exactly: schemaVersion 1, priorities{housework,storage,daylight,budget,privacy,family 0..5}, mustHaveRooms[], avoidRooms[], roomHints[{room,count,sizeJo}], adjacency[{a,b,relation}], orientation{livingFacing,entranceSide}, accessibility{oneLevelLiving,wideCorridors}, pets, workFromHome, notes[], unmappedRequests[], summary)
1. `generatePlansSafe(raw, constraints?)`: optional second param, parsed with `DesignConstraintsSchema` (invalid -> ignored + warning `CONSTRAINTS_INVALID`, never throws).
2. Effects (all deterministic, documented in docs/planner.md): priorities become scoring weights (normalised, bounded) AND influence variant ordering (best-for-priorities first); mustHaveRooms add rooms if missing (study, tatami, walkInCloset, pantry, laundry...), avoidRooms remove optional ones; roomHints adjust count/size within the catalog limits; adjacency adds/removes affinity edges used by zoning/circulation; orientation chooses mirrored layout / living side; accessibility oneLevelLiving prefers 1-storey or bedroom+bath on 1F, wideCorridors raises corridor width; pets/workFromHome add pet-wash/foyer storage or study nook. Anything that cannot be satisfied becomes a plan warning with a stable code (`CONSTRAINT_UNSATISFIED:<what>`) and is listed in the plan summary — never silently dropped.
3. `PlanResult` gets `appliedConstraints` (what changed) per plan.

# TASK T0.4 — Design tokens + base UI components (TASKS.md row 0.4). Requires T0.2 and T0.5 done.

Goal: one place defines colours/typography/radius, and a small set of accessible components exists so later screens
(wizard fields, admin forms) are assembled, not hand-styled. Colour palette is a PLACEHOLDER the client may change, so
everything must flow from CSS variables defined in ONE file.

## Deliverables (frontend, `apps/api/resources/js` + `resources/css`)
1. **Tokens** in `resources/css/tokens.css` (imported by `app.css`), Tailwind 4 `@theme` + CSS variables:
   - Brand scale `--color-brand-50…950` (green, taken from `../old-version/css/base.css`: 950 `#03230f`, 900 `#06381b`, 800 `#0a5228`,
     600 accent `#17a34c`, 700 `#12803e`, tint 300 `#b0e8c6`, tint 50 `#f2fbf6`, gold `#c8a44b`; interpolate the missing steps),
     semantic tokens `background, foreground, card, muted, border, ring, primary, primary-foreground, destructive, success, warning`.
   - **Dark mode**: `.dark` class variant AND `prefers-color-scheme` when no explicit choice; contrast AA (4.5:1 text / 3:1 UI)
     verified by a unit test that computes WCAG contrast ratios for each foreground/background token pair in light and dark.
   - Radius, spacing density, font stack `Noto Sans JP` first (load via `<link>` in `app.blade.php` with `display=swap`, plus a system fallback).
   - A `docs/design-tokens.md` listing every token and its intended use.
2. **shadcn/ui-style components** written by hand in `shared/ui/` (do NOT run the interactive shadcn CLI), using `@radix-ui/*`,
   `class-variance-authority`, `clsx`, `tailwind-merge`, `lucide-react` (exact versions, React 18 compatible). Path alias `@/` -> `resources/js`
   (tsconfig `paths` + Vite alias + Vitest alias + ESLint resolver). Components: `Button` (variants/sizes, loading state, `asChild`),
   `Input`, `Textarea`, `Label`, `Checkbox`, `RadioGroup`, `Select`, `Card`, `Badge`, `Dialog`, `Tabs`, `FormField` (label + control +
   hint + error wired with `aria-describedby`/`aria-invalid`). `cn()` helper in `shared/lib/cn.ts`.
   Touch targets >= 44px on mobile; visible focus ring; every text prop comes from the caller (no literals inside components).
3. **Dev showcase** page rendered only when `import.meta.env.DEV` and the URL hash is `#/ui` (no router exists yet) showing every
   component/state in light and dark. It must be tree-shaken out of the production build (verify by grepping `public/build`).
4. `tailwind-merge`-safe variants; no inline `style={{}}` in new components.

## Tests (Vitest + Testing Library + `vitest-axe`)
- For EVERY component: renders; forwards `className` and `ref`; disabled state is not clickable/focusable; no axe violations
  (default + error + disabled states).
- Button: variants -> expected classes; `loading` sets `aria-busy` and blocks clicks; `asChild` renders the child element;
  Enter/Space activate it.
- Checkbox/RadioGroup/Select/Tabs/Dialog: keyboard behaviour (arrow keys in RadioGroup/Tabs, Space toggles Checkbox, Escape closes
  Dialog and focus returns to the trigger, focus is trapped inside the open Dialog), correct ARIA roles/states.
- FormField: label click focuses the control; error text announced via `aria-describedby`; `aria-invalid` toggles.
- Token contrast test (above) fails if any pair drops below the threshold; token file parse test: every semantic token has a light AND dark value.
- `cn()`: merges conflicting Tailwind classes correctly, ignores falsy values.
- Production build check (script): the dev showcase code is absent from `public/build`.

## Acceptance
`make check` exits 0 twice; `make build` succeeds and bundle growth is reported (before/after gzip sizes in the report; initial JS must stay
< 250 kB gzip per convention). Sabotage (show failing output, restore): (1) lower a token's lightness so contrast < 4.5 -> contrast test fails;
(2) remove `aria-describedby` from FormField -> test fails; (3) remove the Dialog focus return -> test fails.

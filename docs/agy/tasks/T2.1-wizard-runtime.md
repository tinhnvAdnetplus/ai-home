## Deliverables (feature folder `resources/js/features/wizard/`, many small files)
1. **Default form config** `data/default-wizard.ts` exporting a `WizardConfig` for STEP 1-5 following the mockups, with the mockup flaws FIXED (each question once; options hidden by conditions, e.g. choosing one-storey hides "toilet on 2nd floor"; one selection state per card). Texts: `ja` (copy the mockup wording) + `en` + `vi` where easy.
   Use real binding keys from the registry for fields the planner will need (land area, frontage, depth, road side, floors, target area, LDK size, rooms, parking, budget, style...), snake_case field keys, stable option values. It MUST pass `parseWizardConfig` — `data/load-wizard.ts` parses it at module load and throws a descriptive error listing the issues if invalid (fix the data until it passes).
2. **Answers state** `hooks/useWizardAnswers.ts` (useReducer, no new dependency): set/clear answer, go to step, draft persistence in `localStorage` (key includes a hash of the config so a changed form drops stale drafts; wrap storage in try/catch), recompute `resolveWizardState` on every change (derive, do not duplicate in state).
3. **Renderer** `components/fields/*` — one small component per field type (`text`, `textarea` with character counter, `number` with unit switch tsubo/m2 when `allowedUnits` has both, `range`, `select`, `radio`, `checkbox_group`, `image_select` (tiles with an icon placeholder, since real media comes later; selected state like the mockup check badge), `boolean`, `upload` (file picker UI only, files kept in memory, no network)),
   a `FieldRenderer` dispatcher, label/help/required (`必須`) / optional (`任意`) chips, error message, `aria` wiring, keyboard operable, >= 44px targets. Disabled fields / disabled options come from the resolved state. Hidden fields are not rendered.
4. **Shell** `components/WizardShell.tsx` + `StepSidebar`, `StepProgress`, `SectionCard`, `WizardFooter`: desktop = left brand/steps column + main card with step badge, "STEP n" label, title, subtitle, top-right 5-dot stepper (done = check, current = filled, future = grey; STEP 4-5 use the pink accent like the mockups), numbered section cards, primary full-width "次へ" button and secondary "前へ戻る" (last step: "この内容でプランを作成する").
   **Mobile (design it yourself in the same visual language)**: single column, compact "STEP n / 5" header, sticky bottom action bar, no sidebar. Next is blocked while `missingRequired` of the current step is non-empty or a numeric field is out of range; show errors inline and scroll/focus the first one.
5. **Confirmation** `components/WizardSummary.tsx`: after the last step show a readable summary of all visible answers (label -> chosen option labels), an "edit" link per step, and for now a "plan generation is coming next" placeholder button area (no network). Also a `Copy answers as JSON` button for the demo.
6. **Page + route**: `WizardPage` exported from the feature `index.ts`; mount it in `app/App.tsx` for the hash `#/wizard` (keep the existing health page default and the dev showcase). Language switcher stays available (texts from config follow the current language, fallback `ja`).
7. Locale strings for the wizard chrome (buttons, chips, step labels, errors, summary) in `shared/i18n/locales/{ja,en,vi}.json` as a new namespace `wizard` (keep the typed-key setup in `i18n.d.ts` working; the parity check between languages must stay satisfied).

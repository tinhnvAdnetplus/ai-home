# TASK T0.8 — API standard (TASKS.md row 0.8). Requires T0.2 done (Pest + `make check` exist).

Goal: every `/api/*` response follows one predictable contract so the React app and the admin can rely on it
(convention §8). Backend only.

## Deliverables
1. **Always JSON under `/api/*`**, regardless of the `Accept` header (middleware or `shouldRenderJsonWhen`).
2. **Error format = RFC 9457 `application/problem+json`** for every error under `/api/*`:
   `{ "type": "about:blank" | "<url>", "title": "...", "status": 422, "detail": "...", "code": "VALIDATION_FAILED",
      "errors": {"field": ["msg"]}, "request_id": "..." }` (`errors` only for validation).
   Stable, documented error codes in `App\Support\ApiErrorCode` (backed enum): `VALIDATION_FAILED`(422),
   `UNAUTHENTICATED`(401), `FORBIDDEN`(403), `NOT_FOUND`(404), `METHOD_NOT_ALLOWED`(405), `TOO_MANY_REQUESTS`(429,
   include `Retry-After`), `PAYLOAD_TOO_LARGE`(413), `SERVER_ERROR`(500). Map: ValidationException, AuthenticationException,
   AuthorizationException, ModelNotFoundException/NotFoundHttpException, MethodNotAllowedHttpException,
   ThrottleRequestsException, PostTooLargeException, generic HttpException, and any other Throwable.
   - 500 must NOT leak exception class, message, SQL or trace unless `APP_DEBUG=true`; with debug on, add a `debug` object.
   - Titles/details are plain English strings here (admin-editable/i18n texts come in later tasks) — put them in one
     place (`App\Support\ApiProblem`), not scattered.
   Register in `bootstrap/app.php` (`withExceptions`). Non-API routes keep the default HTML behaviour.
3. **Request id**: middleware adds `X-Request-Id` (reuse a valid incoming one: 8–64 chars `[A-Za-z0-9._-]`, otherwise
   generate a UUID) to every API response and puts it in the problem body and in the log context.
4. **Pagination contract**: reusable `App\Http\Resources\PaginatedCollection` giving
   `{ "data": [...], "meta": { "page", "per_page", "total", "last_page" } }`; helper that reads `page`/`per_page`
   from the query: default 20, min 1, max 100 (clamp, never error); invalid values (`abc`, `0`, `-5`, `1e9`) fall back safely.
5. **Rate limiter** named `api` (60/min per authenticated user id, else per IP) applied to the API group; 429 uses the problem format.
6. Keep `GET /api/v1/health` working and unchanged in shape.
7. Short doc `docs/api-contract.md` (English): error codes table, example responses, pagination, request id.

## Tests (Pest). Register test-only routes inside the tests (`Route::get(...)` in `beforeEach`), never in production routes.
- Each error type above: status, `Content-Type: application/problem+json`, body keys, `code`, `request_id` == `X-Request-Id` header.
- Missing API route returns problem+json 404 even **without** an `Accept` header; wrong method -> 405 with `Allow` header.
- Validation: nested + array field names, Japanese messages/values pass through UTF-8 intact, multiple errors per field.
- 500: with `APP_DEBUG=false` the body has no `exception`, `trace`, `file`, `line`, SQL text, or the thrown message;
  with `APP_DEBUG=true` a `debug` object appears.
- Request id: valid incoming id echoed; too short / too long / contains spaces or `<script>` -> replaced by a generated UUID.
- Throttling: configure a tiny limit inside the test, hit it, assert 429 + `Retry-After` + problem body; a different IP is unaffected.
- Pagination: `per_page=1000` -> 100, `0`/`-5`/`abc`/`1e9` -> default or clamped as specified, `page=0`/`abc` -> 1, last page beyond
  total returns empty `data` with correct `meta`; `total`/`last_page` correct for 0, 1, 20, 21, 100 items.
- Non-API route (e.g. a test route under `/web-test`) still returns normal HTML error pages, not problem+json.
- `GET /` SPA and `/api/v1/health` unchanged.

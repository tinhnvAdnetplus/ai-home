# TASK T0.2 — Tooling + test infrastructure (extends TASKS.md row 0.2)

Goal: from now on every change can be checked with ONE command, and the existing code is covered by real tests.
Commit hooks (husky/commitlint/lint-staged) are OUT of scope: there is no git repo yet. Note it under Follow-ups.

## Deliverables

### A. Frontend (`apps/api`, scripts run through `pnpm --filter aihome-app`)
1. **ESLint 9 flat config** (`eslint.config.js`): `typescript-eslint` (strict + type-checked), `eslint-plugin-react`,
   `react-hooks`, `jsx-a11y`, and **`eslint-plugin-boundaries`** enforcing convention §2 for `resources/js`:
   layers `app -> features -> shared`; a feature must not import another feature's internals; nothing in `shared`
   imports from `features`/`app`. Rules on: no `any` (`no-explicit-any`), no non-null assertion, `no-console`.
   Create the layer folders with one tiny, real file each so the rule has something to protect
   (`resources/js/{app,features,shared}`) — move `main.tsx`'s bootstrap into `app/` only if you keep the Vite entry
   path in `vite.config.ts`/`app.blade.php` consistent and the build still works.
2. **Prettier** (`.prettierrc`, `.prettierignore`): 4 spaces to match `.editorconfig`; single quotes; trailing commas.
3. **Vitest** + `@testing-library/react` + `@testing-library/jest-dom` + `@testing-library/user-event` + `jsdom`.
   Config in `vitest.config.ts` (or inside `vite.config.ts` without breaking the Laravel plugin). `setupTests.ts`.
4. Scripts in `package.json`: `lint`, `lint:fix`, `format`, `format:check`, `typecheck`, `test`, `test:watch`.
5. Real tests for the existing health page (`App.tsx`): loading state, success state (status ok / db up and db down),
   HTTP error (500) -> error UI, network failure (fetch rejects) -> error UI, malformed JSON / wrong shape -> error UI,
   "retry" button re-fetches and recovers. Mock `fetch` per test (no network).
6. **Prove the boundary rule works**: create a temporary file in one feature importing another feature's internals,
   run lint, show it fails, delete the file. Record this in the report (sabotage section).

### B. Backend (`apps/api`)
1. **Pest 3** + `pestphp/pest-plugin-laravel` (keep `phpunit.xml`; tests run on sqlite `:memory:`; do not touch dev MySQL).
   Convert nothing that already works unless needed; the skeleton `ExampleTest`s may be replaced by the tests below.
2. **Larastan** (`larastan/larastan`) at **level 6** with `phpstan.neon` covering `app`, `routes`, `tests`; baseline only if
   unavoidable (prefer fixing).
3. **Pint** config `pint.json`: `psr12` preset + `declare_strict_types`. Make existing PHP files pass (add
   `declare(strict_types=1);`).
4. `composer.json`: keep exact versions for new packages, add `"config": {"platform": {"php": "8.2.0"}}`, scripts
   `test`, `lint` (pint --test), `lint:fix`, `stan`, `check` (lint + stan + test).
5. Pest tests (use `$this->withoutVite()` so tests never depend on `public/build`):
   - `GET /api/v1/health` -> 200 JSON with exactly keys `status`, `db`, `time`; `db` is `up`; `time` parses as ISO-8601 UTC.
   - Same endpoint when the DB throws (mock `DB::select` to throw) -> still HTTP 200 with `"db":"down"`.
   - SPA catch-all returns the `app` view with 200 for `/`, `/admin/config`, `/a/b/c`, `/wizard/step-2`, a Japanese path
     (`/プラン`) and a path with a trailing slash.
   - NOT swallowed by the SPA: `/api`, `/api/`, `/api/v1/nope` -> not the SPA view (404; JSON when `Accept: application/json`).
   - Boundary: `/apiary` and `/api-docs` ARE the SPA (they only *start with* "api").
   - A POST to `/` returns 405 (not the SPA).

### C. Makefile (repo root `new-version/`)
Targets `lint`, `fix`, `test`, `typecheck`, `check` (= everything: Pint, Larastan, Pest, ESLint, Prettier check, tsc, Vitest).
They run inside containers (`docker compose exec -T ...`) and return non-zero on any failure. Add them to `make help`.

## Acceptance (you must show command output for each)
- `make check` exits 0 twice in a row.
- Vitest: >= 8 tests passing; Pest: >= 9 tests passing; Larastan level 6: 0 errors; ESLint/Prettier/tsc/Pint: 0 problems.
- Sabotage evidence: (1) boundary lint violation fails, (2) change the status code or the `db` key in the health route ->
  a Pest test fails, (3) make `App.tsx` ignore `response.ok` -> a Vitest test fails. Restore afterwards.
- `make build` still succeeds and `http://localhost:8080/` still serves the app (check with curl; Vite dev server may be running).

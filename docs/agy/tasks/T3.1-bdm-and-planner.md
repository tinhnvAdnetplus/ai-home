## Package A — `packages/bdm` (`@aihome/bdm`)
Zod schema + types for `BuildingModel` v1 (all geometry in integer millimetres, y axis pointing from the road into the plot like the prototype, documented): `schemaVersion`, `meta {generator, seed, inputHash}`, `site {boundary polygon, areaM2, road {side, widthMm}, setbacks}`,
`floors[] { level, elevationMm, heightMm, rooms[] {id, type (enum: ldk, living, dining, kitchen, bedroom, childRoom, washitsu, bath, wash, toilet, entrance, hall, corridor, stairs, storage, closet, walkInCloset, pantry, laundry, study, balcony, ...), name, polygon, areaM2}, walls[] {id, a, b, thicknessMm, kind: exterior|interior, },
openings[] {id, wallId, offsetMm, widthMm, heightMm, sillMm, kind: door|slidingDoor|window|largeWindow|entrance}, fixtures[] {id, kind, polygon/pos, rotation}, stairs[] {...} }`, `roof {kind, pitch, overhangMm}`, `parking`, `warnings[]`.
Export `parseBuildingModel(input: unknown)` (never throws; returns ok/issues like `parseWizardConfig`, includes cross checks: unique ids, openings reference existing walls, rooms inside the site, positive dimensions) and helper functions `roomsOf`, `totalFloorAreaM2`, `boundingBox`. Hostile-input rules: bounded cost, no throw, no prototype keys.

## Package B — `packages/planner` (`@aihome/planner`)
1. `PlanInput` type = the planner inputs of the prototype (`v.*` fields) mapped one-to-one to the binding-registry keys (document the mapping table in `docs/planner.md`), with a Zod schema + `normalizePlanInput(raw)` applying the same defaults/clamping as the prototype.
2. `PlannerConfig` (all tunables as data, convention section 7): grid module (910 mm), room catalog (min/max/default jo sizes, zone, adjacency preferences), scoring weights, number of proposals, legal defaults (coverage ratio / floor-area ratio limits are INPUT values, never hard-coded). `defaultPlannerConfig` holds the prototype's values.
3. `generatePlans(input: PlanInput, config?: Partial<PlannerConfig>, seed?: number): PlanResult` returning `{ plans: Plan[3], warnings }` with each `Plan = { id, label, score {housework, storage, daylight, budget, total}, warnings: Issue[], model: BuildingModel, summary {floorAreaM2, tsubo, roomsList} }`.
   Pure + deterministic (same input + seed -> byte-identical JSON; no `Math.random` without the seeded PRNG, no `Date`), never throws for arbitrary `unknown` input (use `generatePlansSafe(unknown)` returning `{ok:false, issues}` for invalid input), bounded cost for hostile numbers (land 1e9 tsubo, NaN, negative, 1000 rooms requested -> clamped/rejected with issues, finishes in < 1 s).
4. Port in clear modules (each < 150 lines): `grid.ts`, `zoning.ts`, `rooms.ts`, `circulation.ts` (adjacency graph + BFS door placement guaranteeing every room reachable), `openings.ts`, `stairs.ts`, `second-floor.ts`, `legal.ts` (coverage/floor-area ratio and dimension checks -> warnings with stable codes), `scoring.ts`, `variants.ts` (3 proposals: standard / mirrored+daylight / compact+entrance swap), `to-bdm.ts` (grid plan -> `BuildingModel`).
5. `docs/planner.md`: algorithm overview, input mapping, config knobs, warning codes, limits, and a list of intentional differences from the prototype.

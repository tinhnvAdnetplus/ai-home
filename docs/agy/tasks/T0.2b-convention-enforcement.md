Target structure (feature-based, one-way imports `app -> features -> shared`):
```
app/            main.tsx (Vite entry)  App.tsx  providers.tsx (QueryClientProvider)  error-boundary wiring
features/health/
  api/          health-api.ts          # the ONLY place that calls fetch for health; parses with Zod
  hooks/        useHealth.ts           # TanStack Query useQuery wrapper
  components/   HealthCard.tsx  HealthRow.tsx  (+ HealthSkeleton.tsx)   # presentational, each < 150 lines
  schemas/      health-schema.ts       # Zod schema + inferred type (single source of truth)

shared/ui/      ErrorFallback.tsx (accessible error UI with retry button)
```
Requirements:
- Move `main.tsx` to `app/main.tsx` and update `vite.config.ts` input, `resources/views/app.blade.php`, `tsconfig.json`,
  ESLint/Vitest configs accordingly. `make build` and the served page must still work.
- **Server state via TanStack Query** (`@tanstack/react-query`, exact version, React 18 compatible): no `useEffect` for fetching,
  no copying query data into `useState`. Retry button = `refetch`. Sensible defaults in providers (e.g. `retry: 1` for queries,
  `refetchOnWindowFocus: false`). Create the `QueryClient` once (not on every render).
- **Zod** (`zod`, exact version) parses the API response at the boundary; no `as` casts, no hand-written duplicate type guards.
- Component states: loading (skeleton), error (message + retry), success. An `ErrorBoundary` (`react-error-boundary`, exact version)
  around the app root renders `ErrorFallback`.
- Remove ALL inline `style={{}}`; use Tailwind utility classes (mobile-first, >= 44px touch targets, visible focus ring, semantic
  elements, labelled controls). Keep the visible text the same for now (i18n comes in T0.5; do not invent translations).
- Function components only, named exports (default export only for lazy pages — none yet), props typed as `type Props`, no `React.FC`,
  no component > 150 lines, no nested component definitions, stable `key`s.
- Tests move next to their code and are rewritten for the new structure (`HealthCard.test.tsx`, `useHealth.test.tsx`,
  `health-api.test.ts`, `http.test.ts`, `ErrorFallback.test.tsx`, an app-level test). Keep every scenario the old `App.test.tsx`
  covered (loading, ok/db up, db down, HTTP 500, 404, network failure, malformed payload, non-object payload, retry, refresh) and add:
  empty body, invalid JSON, response with extra fields (accepted), `time` not a string, request aborted. Each test uses a fresh `QueryClient`.

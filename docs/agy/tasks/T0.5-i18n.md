# TASK T0.5 — i18n (TASKS.md row 0.5). Requires T0.2 done (Vitest, ESLint, `make check`).

Goal: no user-visible string is hard-coded in components; Japanese is the default language, English/Vietnamese are
ready. (Later, admin-edited texts will arrive from the server and use the same keys — see convention §7.2.)

## Deliverables (frontend, `apps/api/resources/js`)
1. `i18next` + `react-i18next`, exact versions. Code in `shared/i18n/`:
   - `init.ts` exporting `initI18n(lang?)`: default and fallback language `ja`; supported `ja`, `en`, `vi`;
     initial language order: explicit arg -> `localStorage` key `aihome.lang` (wrapped in try/catch: storage may throw) ->
     `<html lang>` -> `ja`. Unsupported/garbage values fall back to `ja`. `changeLanguage` updates `<html lang>` and persists.
   - Locale files `shared/i18n/locales/{ja,en,vi}.json` split into namespaces `common`, `health`, `errors`.
   - **Typed keys**: TypeScript resource typing (`declare module 'i18next'`) so a wrong key is a compile error.
   - `Intl`-based helpers in `shared/lib/format.ts`: `formatNumber`, `formatDateTime` (UTC ISO input, shown in `Asia/Tokyo`
     for `ja`), tested for ja/en/vi.
2. Wrap the app in the provider (in `app/`), and **move every string of the existing health page into the locale files**
   (Japanese is the source of truth; provide en + vi translations). No literal UI text left in `App.tsx`.
   Also put `lang="ja"` handling consistent with `app.blade.php` (the blade `lang` attribute stays driven by Laravel).
3. A language switcher component (`shared/ui/LanguageSwitcher.tsx`): accessible `<select>` with a visible label (translated),
   keyboard operable, persists the choice.
4. ESLint rule or test that blocks regressions: add `eslint-plugin-i18next` (`no-literal-string`, JSX text only, with a small
   allow-list for punctuation/symbols) **or** an equivalent custom test that scans `resources/js/**/*.tsx` for JSX text containing
   letters (ja/en/vi) and fails. Whichever you choose must be demonstrated to fail on a violation.

## Tests (Vitest)
- Key parity: every key in `ja` exists in `en` and `vi` and vice versa (fails and names the missing key); no empty strings;
  interpolation placeholders (`{{name}}`) are identical across languages for each key.
- Default language is `ja` when nothing is stored; `localStorage` value `en` is honoured; `localStorage` containing garbage,
  an unsupported code (`fr`), or throwing on access -> falls back to `ja` without crashing.
- Missing key in `en` falls back to `ja`; unknown key returns the key (and does not throw).
- `changeLanguage('vi')` updates rendered text, `<html lang>`, and storage; switching back works.
- Health page renders in ja, en, vi for loading/success/error states (reuse the T0.2 fetch mocks).
- Formatters: `formatNumber(1234567.891)` in ja/en/vi; `formatDateTime('2026-10-12T02:35:33Z')` -> Tokyo time for `ja`;
  invalid input does not throw (returns a safe fallback) — decide and document the fallback.
- LanguageSwitcher: label associated with the select (`getByLabelText`), changing the option switches the UI, keyboard works,
  and no axe violations if `vitest-axe` is available (add it, exact version).
- Lint rule/test: a temporary component with hard-coded text must fail it; remove the file afterwards.
